# 个人介绍网站设计规范

## 目标

把已确认的四张视觉稿重建为可交互、可响应、可直接部署的个人介绍网站。`网页/index.html` 是唯一入口，双击即可浏览；部署 GitHub Pages 时只需提交 `网页` 文件夹。

## 页面结构

主站采用单页连续全屏滚动，顺序为：首页、经历、兴趣、联系。导航仅保留“首页 / 经历 / 兴趣 / 联系”，点击后滚动到对应章节。兴趣页中的古典乐、运动、电影是三个独立 React 模块，分别预留 `#/interests/music`、`#/interests/sports`、`#/interests/movies`，本阶段不制作详情页。

## 技术与交付形态

- React + Anime.js + 可复现的本地构建脚本。
- 发布物使用相对路径，不能依赖工作区外层文件。
- 根目录保留可双击运行的预构建 `index.html` 与经典脚本资源；不得要求用户先启动开发服务器。
- 开发源码、测试、素材和构建配置均包含在 `网页` 内。
- 兴趣详情使用 Hash 路由，保证本地文件协议和 GitHub Pages 都不会刷新 404。

## 视觉系统

四个章节统一使用黑炭纸纹背景、暖白主文字、铜金细节与单一橙色强调。页面必须用真实 DOM、文字、图片与独立图层重建，不得把整张设计稿作为背景。首页沿用人物、两城建筑和路线构图；经历页沿用档案编辑布局；兴趣页沿用三卡片布局及“我的生活，不止一种节奏。”；联系页沿用编辑分屏及左下图书馆正面线稿。

## 动画系统

全站由一个 `MotionDirector` 统一管理章节联动，章节组件只管理自身内容。固定的铜金坐标层、橙色定位点、导航状态和章节编号贯穿全站。

- 首页：环境光和定位信息建立空间，人物从暗部对焦，标题分行出现；两城建筑以裁切层错峰拼装并归位。具体顺序由整体时间轴决定，不执行“线条先于人物”的固定规则。
- 首页到经历：橙色定位点从城市路线进入经历页并成为时间线当前节点。
- 经历：只有纵向时间线使用 SVG `createDrawable()` 擦除/绘制；荣誉卡随节点进入。高级 AI 证书继续隐藏证书编号，物理证书和初级 AI 证书不展示。
- 经历到兴趣：档案边框横向展开为三张兴趣卡的结构基线。
- 兴趣：三模块错峰进入，悬停使用图像推进、标题位移与箭头响应；模块内容不可烘焙到背景图。
- 兴趣到联系：三个橙色箭头收束成联系页路径；图书馆以空间拼装进入，二维码只做虚焦到清晰，不改变码体比例。
- 反向滚动时全局联动可逆。
- `prefers-reduced-motion: reduce` 时取消透视、路径运动和错峰，仅保留即时状态与短淡入。

## 数据与可修改入口

`src/config/siteConfig.js` 集中保存电话、邮箱、微信二维码路径和三个兴趣详情路径。联系方式不得写死在组件内。二维码使用 `object-fit: contain` 和纯白静区，不裁切，不叠加滤镜。

## 素材

从外层工作区复制并在 `网页/assets` 内独立保存：头像、微信二维码、高级 AI 证书、AMC 证书、喜马拉雅数据截图、首页与图书馆所需线稿及兴趣页图片。构建及运行不得引用 `../图片`、`../证书` 或 `../design-concepts`。

## 响应式与可访问性

- 桌面端以 1586×992 设计稿比例为主要校验基准。
- 平板和手机改为自然纵向流，避免固定高度裁切正文。
- 导航、兴趣卡和联系方式具备键盘焦点；图片提供替代文本。
- 颜色与字号在暗色背景上保持可读。

## 验收标准

1. 双击 `网页/index.html` 可完整显示页面和动画，无网络服务器依赖。
2. 只复制 `网页` 到任意位置后仍可运行。
3. 四个章节导航、滚动联动和反向状态切换正常。
4. 三个兴趣模块保持独立组件和集中路由配置。
5. 电话、邮箱和微信二维码可只修改配置或图片完成替换。
6. 二维码可扫描；高级 AI 证书编号不可见。
7. 桌面、平板、手机无横向溢出。
